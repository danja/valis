# Model a machine or a record's method

Done for the 1983 electronic record: `docs/new-order-track.md` is the output to copy.

## Method

1. **Research with several sources and keep their disagreements.** Search, then read the band's or maker's own
   account first (an interview transcript, a manual), then reference pages, then retrospective articles. Record
   a claim only with its source, and write "sources disagree" with both values when they do. Tempo and key
   databases are estimates and often wrong; do not use them to fix a key.
2. **Separate what is known from what is not.** The document has a section for each, so the unknowns are not
   filled in later by accident.
3. **Say what is borrowed.** For work "in the style of" something, write down what is borrowed (method,
   instrumentation, sound, form) and what is not (melodies, patterns as written, samples, names, logos).
   Samples of someone's record are not used; a synthesised stand-in is made instead.
4. **Write the requirements from the research**: the piece (length, tempo, form, mix), and a table of circuits.
   For each circuit: what it models, what Valis already has to build it from, and what is missing.
5. **Find the gaps and decide.** A missing element gets a short spec in the document and an entry in `TODO.md`;
   a missing sound is made from what exists. Do not build the missing element unless asked.
6. **Build in the order of the table, test each (`test-an-instrument`), then do the piece (`write-a-song`).**
7. **Keep the status section current** at the end of the document: built, not built, not heard.

## Documentation rules (CLAUDE.md)

Plain technical English, no em dashes, no invented jargon, a link for any concept that is not common knowledge.
Do not give a person's pronouns unless stated. Put a link to each source used.
