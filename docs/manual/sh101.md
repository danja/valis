# Case study: SH-101 subtractive synthesiser

The Roland SH-101 (1982) is a single-oscillator monophonic synth with a
ladder filter and a simple ADSR. This circuit reproduces its signal path in
Valis. The full Turtle is at `examples/sh101.ttl`.

## Signal path

```
MidiPitch ─────────────────────────────► Oscillator (VCO)
                                               │ audio
LFO (vibrato) ─── ControlArc, depth=0 ────────┘
                                               ▼
                                         Ladder (VCF)
                                               │ audio
Envelope ──► Scale(400–8000 Hz) ── control ───┘ ← filter sweep
                                               ▼
Envelope ─────────────── control ──────► VCA
                                               │ audio
                                          Output
```

## Key elements

### MidiPitch

Outputs the currently held MIDI note as a frequency in Hz. Holds the last value
between notes (default A4 = 440 Hz until the first note-on arrives).

```turtle
:pitch a val:MidiPitch .

:aPitchOsc a val:ControlArc ;
    val:from [ val:node :pitch ; val:port "out" ] ;
    val:to   [ val:node :osc   ; val:port "frequency" ] .
```

### VCA (voltage-controlled amplifier)

Takes a 0–1 control signal at `cv` and multiplies the audio linearly. Connecting
the Envelope output here gives a natural amplitude contour - the envelope's 0–1
range maps directly to silence→full level with no extra scaling.

```turtle
:vca a val:VCA .

:aEnvVca a val:ControlArc ;
    val:from [ val:node :env ; val:port "out" ] ;
    val:to   [ val:node :vca ; val:port "cv"  ] .
```

### Control arcs replace fixed values

A control arc that reaches a port **replaces** the port's declared value every
block. This is intentional and essential for pitch tracking: `MidiPitch → Osc.frequency`
must write an absolute Hz value, not add to a default. The same rule applies to
every control arc in the circuit.

The consequence for filter control: you cannot have both a fixed `val:cutoff` on
the Ladder instance *and* a control arc targeting `cutoff` - the arc wins every
block, making the fixed value unreachable. This means the Ladder's resting cutoff
must live somewhere in the control path, not on the element itself.

```turtle
:vcf a val:Ladder ;
    val:resonance 0.3 ;
    val:drive     1.0 .
# val:cutoff is intentionally absent - the control arc from :envScale
# sets the cutoff every block, overriding any fixed value here.
```

### Scale - bridging 0–1 to physical units

The Envelope output is 0–1. The Ladder filter expects a cutoff in Hz. `val:Scale`
maps the 0–1 control signal to a [min, max] range. Because the control arc
*replaces* the cutoff entirely, the Scale's `min` value *is* the resting cutoff
(envelope closed). The Scale's `max` value is the cutoff at the envelope's peak.

```turtle
:envScale a val:Scale ;
    val:min 400.0 ;    # Hz - base cutoff when envelope is silent
    val:max 8000.0 .   # Hz - cutoff at envelope peak

:aEnvScale a val:ControlArc ;
    val:from [ val:node :env      ; val:port "out" ] ;
    val:to   [ val:node :envScale ; val:port "in"  ] .

:aScaleVcf a val:ControlArc ;
    val:from [ val:node :envScale ; val:port "out"    ] ;
    val:to   [ val:node :vcf      ; val:port "cutoff" ] .
```

With these settings, the filter sweeps from 400 Hz (envelope closed, between
notes) to 8000 Hz (envelope peak, attack transient).

### Host parameters for Scale.min and Scale.max

The "Cutoff" knob in the host controls `Scale.min` - the filter's resting
frequency when no note is held. The "Filter Peak" knob controls `Scale.max` -
the cutoff the filter reaches at the envelope's peak.

Because Scale's ports have a generic ±1e6 range (useful for non-frequency
applications), the `val:Param` declaration overrides the range for display:

```turtle
:p1 a val:Param ; val:slot 1 ; val:target :envScale ; val:property val:min ;
    lv2:name "Cutoff" ; lv2:symbol "cutoff" ; units:unit units:hz ;
    lv2:minimum 20.0 ; lv2:maximum 20000.0 .

:p7 a val:Param ; val:slot 7 ; val:target :envScale ; val:property val:max ;
    lv2:name "Filter Peak" ; lv2:symbol "filter_peak" ; units:unit units:hz ;
    lv2:minimum 20.0 ; lv2:maximum 20000.0 .
```

The `lv2:minimum`/`lv2:maximum` on the `val:Param` node override the port's
intrinsic range for this binding only, so the host's automation lane and UI show
sensible Hz values without changing the ontology.

### Vibrato

The LFO drives the oscillator frequency with `val:depth 0.0` by default - set
depth to a small positive value (e.g. 0.02 for about a semitone) to introduce
vibrato:

```turtle
:aLfoOsc a val:ControlArc ; val:depth 0.02 ;
    val:from [ val:node :lfo ; val:port "out" ] ;
    val:to   [ val:node :osc ; val:port "frequency" ] .
```

## Processing order

Control sources (MidiPitch, Envelope, Scale) must be processed before the
elements they drive, so that each block sees fresh values. Valis's compiler
performs a topological sort that includes control arcs - a control arc `A → B`
guarantees A is processed before B in the same block.

Without this, pitch and filter modulation would lag by one block (~0.7 ms at
44.1 kHz) - audible as a subtle click on fast attacks and slightly blurred
pitch tracking.

## Loading the circuit

Paste `examples/sh101.ttl` into the Turtle editor tab, or load it via
**File → Load Circuit…**. The nine host parameters (slots 0–8) cover:

| Slot | Name         | What it controls                     |
|------|--------------|--------------------------------------|
| 0    | Osc Shape    | Waveform (0=sine … 3=square)         |
| 1    | Cutoff       | Filter resting frequency (Hz)        |
| 2    | Resonance    | Filter self-resonance (0–1)          |
| 3    | Attack       | Envelope attack time (ms)            |
| 4    | Decay        | Envelope decay time (ms)             |
| 5    | Sustain      | Envelope sustain level (0–1)         |
| 6    | Release      | Envelope release time (ms)           |
| 7    | Filter Peak  | Filter cutoff at envelope peak (Hz)  |
| 8    | Vibrato Rate | LFO rate (Hz)                        |
